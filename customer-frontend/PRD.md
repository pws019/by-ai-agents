# customer-frontend PRD（精炼版，供设计稿参考）

## 一句话定位

一个轻量的电商客服 Agent 对话前端，playground 风格：左侧会话列表 + 右侧聊天窗口，
支持会话的增删改查和与 Agent 的多轮对话。

## 用户与身份

- 无需登录，免注册直接用
- 每个浏览器首次访问会分配一个匿名身份（Cookie 存 UUID），该身份下的会话只有这个浏览器能看到
- 不做多用户协作、不做会话分享

## 页面结构：整体两栏布局

```
┌─────────────┬──────────────────────────────┐
│             │                               │
│  会话列表    │        聊天窗口                │
│  （常驻）    │      （随选中会话切换）         │
│             │                               │
│             │                               │
└─────────────┴──────────────────────────────┘
```

切换会话只替换右侧内容，左侧列表不重新加载、不闪烁、不整页跳转。

**左侧栏宽度是布局常量，不是内容撑开的**：左侧宽度由外层布局固定写死（比如 Grid/Flex 分栏时
显式指定像素宽度），跟里面渲染的是"0 条会话的空状态"还是"20 条会话的列表"完全无关。这样
从零会话到有会话之间，侧边栏不会跟着变宽/跳动，只是里面的内容从空白变成列表项。

## 会话创建时机：懒创建，不设"必须先建会话"这一步

- 会话（Memory Thread）**不是**靠点一个"新建会话"按钮同步创建的，而是在用户发出**第一条消息**时
  才隐式创建
- 效果：首次访问（全局零会话）和点了"新建会话"，右侧看到的是**同一个状态**——一个已经可以直接
  打字的聊天窗口，不需要额外多点一步
- "新建会话"按钮的作用因此变成"另起一个新话题"（结束当前对话、开始下一个），不是"必须先点这个
  才能开始聊天"

## 左侧：会话列表（SessionSidebar）

**功能**：
- 展示所有**已经产生过对话**的会话，按最近更新时间倒序（还没发过消息的"草稿"状态不在列表里，
  因为它对应的 thread 还没被创建）
- 当前打开的会话高亮
- 顶部固定"新建会话"入口：点击后右侧切到"待创建"的空聊天态，列表本身不会立刻多一条
- 每条会话支持：重命名、删除
- 删除当前正打开的会话后，需要有明确的后续状态（回到"待创建"的空聊天态，或跳到相邻会话）

**每条会话项展示内容**：
- 会话标题（首条消息发出后可以用消息内容自动生成标题，见下）
- 最近更新时间

**状态**：
- 空状态：全局一条会话都没有时，列表区域保持轻量留白即可，不需要大段引导文案——因为右侧
  已经是可以直接开始输入的状态，不需要靠左侧文案再引导一次
- 加载态：列表拉取中
- 错误态：后端服务不可用时的提示（不能空白/崩溃）

## 右侧：聊天窗口（ChatPanel）

**"待创建"状态**（全局零会话时的首次访问 / 点了"新建会话"）：
- 不是拦截式的引导页，就是一个可以直接输入的聊天窗口
- 消息区域可以放一句轻量欢迎语（比如"有什么可以帮您？"），不强制要求有 CTA 按钮
- 输入框 + 发送按钮从一开始就是可交互的

**已有会话（选中已存在的会话）**：
- 顶部：当前会话标题
- 中间：消息列表，区分用户气泡 / Agent 气泡，历史消息随进入会话时加载
- 底部：输入框 + 发送按钮

**发送消息交互**：
- 如果当前是"待创建"状态，发送第一条消息时先创建 thread，再发消息，对用户来说是无感的一步到位
- 发送中要有 loading 反馈，防止重复提交
- 失败要有明确错误提示（不是静默失败）
- Agent 侧会调用外部工具（查物流 / 查知识库），理想情况下应有"正在查询…"这类中间状态展示，
  而不是一直空白等到最终答案（P1，非首版必需）
- 会话的第一条消息发出后：thread 被创建、左侧列表会新增这一条会话项；标题可以用首条消息内容
  自动生成（P1，非首版必需，首版可以先用消息前几个字截断当标题）

## 明确不做（设计稿不用考虑）

- 登录 / 注册 / 用户设置
- 多 Agent 切换（固定只对接客服 Agent 一个）
- 消息编辑、重新生成、消息级操作（复制除外可选）
- 会话分享、多人协作
- 移动端专门适配（先保证桌面端可用即可，非强制响应式）

## 设计基调建议

客服工具属性，界面应偏克制、功能优先，不需要强营销感或重视觉表现；对话区域是绝对主角，
侧边栏保持轻量、不抢注意力。
