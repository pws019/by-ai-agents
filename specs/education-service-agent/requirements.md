# AI 全栈训练营学员服务 Agent — 开发需求

版本：2026-09-20。状态：可开始实施的 V1 规格；业务默认值见下文。

## 1. 目标与阅读顺序

将现有电商客服 Demo 升级为可复现、可评估、可在面试中解释设计取舍的教育行业 Agent 项目。实施时依次阅读本文件、design.md、tasks.md、learning-plan.md、CLAUDE-HANDOFF.md。

核心交付是两个完整场景：
1. 学员咨询 → 查询本人报名 → 确认申请 → 老师处理 → 查询真实结果。
2. 学员提问 → 定位知识点 → 查询先修关系 → 检索本期讲解 → 返回有权限的回放片段和引用。

本项目不是完整 LMS、课程商城或自动教学系统。不得把模拟业务和离线评估写成公司线上业绩。

## 2. 已确认业务事实

- 当前只销售 AI 全栈课程，按第 1 期、第 2 期等班期组织；只对外销售当前招生期。
- 历史上有其他课程，需保留历史记录，但 V1 不做旧课程销售、课程推荐商城。
- 课程先直播，之后形成录播。已知学员权益是观看所报名班期的回放。
- 没有可对接的现成业务 API，需要自行实现数据库、业务 API、老师页面。
- 转班由学员申请，老师酌情审批，没有已知自动资格限制。
- 退费量少，由老师逐单协商，不存在已确认的自动计算公式。
- 用户希望学习知识图谱，V1 必须有课程知识图谱的真实查询与评估，不能只画图。
- 云端训练 QLoRA 可行；云资源开通和训练属于后续独立阶段。

## 3. 默认值与未明确规则

以下为可运行的产品默认值，不声称是公司现行政策。

| 问题 | V1 处理 | 是否阻塞开发 |
|---|---|---|
| 回放有效期 | 不设置过期时间；不向用户宣称永久有效 | 否 |
| 转班后旧回放权益 | 老师批准时必须选择保留或撤销，写入审计 | 否 |
| 学员不知道目标班期 | 允许提交 targetCohortId=null，老师补充处理 | 否 |
| 没有未来班期 | 不编造班期；仍可提交无目标班期的申请 | 否 |
| 目标班期变化 | 与学员原确认内容不同，须学员再次确认后才能批准执行 | 否 |
| 退款金额 | 老师协商录入，学员确认金额后批准；不自动试算 | 否 |
| 实际付款/退款通道 | 不接支付；订单 seed/老师导入，退款结果人工登记且明确标记 | 否 |
| 学习进度来源 | 老师维护或导入；仅表示记录的完成情况，不等同于掌握程度 | 否 |
| 回放资源与字幕 | 先用明确标注的合成字幕/示例视频验证，再替换为授权资料 | 否 |
| 老师权限 | V1 机构内一个 teacher 角色；不做多机构 SaaS | 否 |

有新业务事实时更新本表并记录决策，禁止开发者自行发明退费比例、转班次数、就业承诺等政策。

## 4. 角色与页面

### 访客
- 可查询当前招生期的价格、日期、大纲和已发布 FAQ。
- 不可查询学员信息、受限字幕、回放链接、个人申请。
- 需要个人服务时引导登录；不得依赖用户在聊天里自报身份。

### 学员
- 登录后查看自己的报名、所属班期、权益、课表和学习进度。
- 聊天中查询知识、查找本期回放、获得先修知识导航。
- 创建、确认、补充、撤回和查询自己的转班/退费申请。
- 主动请求老师接管。

### 老师
- 管理班期、课程版本、课次、回放元数据、订单和报名。
- 维护或导入学习进度；审核知识文档、知识点和先修关系。
- 查看申请队列，要求补充、提出方案、批准、拒绝、登记退款结果。
- 接管会话、回复、结束接管，查看必要的执行依据和审计记录。

### 页面清单
1. 登录页（演示账号种子，不开发注册找回全流程）。
2. 学员聊天页：流式回复、引用、回放卡片、申请确认卡片、转人工状态。
3. 我的学习：报名、课表、进度、回放入口。
4. 我的申请：列表、详情、状态时间线、补充/确认/撤回。
5. 老师申请工作台：列表、详情、审批和退款登记。
6. 老师内容管理：班期、课次、文档、图谱审核；可用简单表格表单。
7. 老师会话工作台：待接管、已接管、消息和交接摘要。

## 5. 功能需求

### F-001 身份与数据隔离
- 使用服务端登录会话。所有个人数据 API 和 Agent 工具从可信上下文获取 actor。
- 学员只能操作自己的资源；老师才能审批。不能通过篡改 userId/threadId 访问别人资源。
- 回放入口再次验证有效权益，不仅靠检索时的过滤。

### F-002 教育业务事实
- 课程、内容/权益版本、班期独立建模；订单关联购买时协议版本，报名关联班期。
- 一个 AI 全栈课程最多一个当前销售班期；未发布价格、日期如实返回 unknown，不生成猜测。
- 历史课程/班期可查询其已有报名；招生回答只用当前对外发布内容。

### F-003 招生及在读咨询
- 大纲和 FAQ 从已发布知识检索；价格和开课日期从业务 API 获取。
- 老学员权益使用其报名关联版本，不能用当前招生宣传替代。
- 不提供没有来源的保就业、薪资、终身回放等承诺。

### F-004 申请与确认
- 两种申请：transfer、refund；必需本人 enrollmentId 和原因。
- 转班目标允许为空；退款金额不得由模型填写。
- 聊天工具先创建申请草稿/确认卡片，只有学员经认证点击确认后才成为 submitted。
- 卡片包含类型、报名、目标班期（如有）、原因、revision；更改关键字段后旧卡片失效。
- 同一报名、同类型最多一张未结束申请；重复提交返回已有结果。
- submitted/needs_info/awaiting_student_confirmation 可撤回；批准后不可直接撤回。

### F-005 老师处理
- 无需自动转班资格判断，无需自动退费公式。
- 老师可要求补充、拒绝（原因必填）、提出修改方案或批准。
- 若转班目标原来为空或发生改变，进入学员二次确认；拒绝方案返回待老师处理。
- 退费需先提出金额和说明，学员确认后才能批准；金额为非负整数分，不超过订单可退余额。
- 转班批准：目标班期有效、权益处理已选择；事务内变更报名、记录历史和审批。
- 退费批准只表示同意；executionStatus=pending。老师登记结果后才为 completed。
- 无支付对接时页面显示“老师登记退款结果”，不冒充支付平台验证。
- 两个老师并发审批只有一个成功，其余获得状态冲突提示。

### F-006 人工接管
- 学员主动请求、证据不足且无法澄清、工具持续失败可进入人工队列。
- 摘要包含问题、已核验事实、相关申请、工具失败和待处理事项；不可包含猜测事实。
- 会话状态 bot → queued → human → bot/closed；queued 状态只反馈排队并记录消息，暂停自动业务操作。
- human 状态不自动生成客服回复；老师主动结束接管后才能恢复。
- 接管与申请审批是两个概念，审批不要求老师一直占用聊天会话。

### F-007 回放 RAG
- 输入字幕优先支持 SRT/VTT，另支持带 sourceId 的 Markdown 讲义；V1 不做语音转写。
- 分片保留 lessonId、cohortId、contentVersion、startSeconds/endSeconds、sourceId。
- 讲义没有时间戳时不得伪造跳转时间；返回文档引用。
- 来源权限在检索前限制；只有已发布且当前版本的片段可用于回答。
- 更新、删除、撤回资料后旧片段不再命中；支持失败后重新入库。
- 无足够依据时说明没有找到并澄清或交接。召回/重排分数不是回答正确概率。
- 回答引用能够定位原文；回放卡片指向应用受控播放路由。

### F-008 课程知识图谱（V1 必做）
- 实体：Concept、Cohort、Lesson、Segment。
- 关系：Concept REQUIRES Concept；Lesson IN_COHORT Cohort；Lesson HAS_SEGMENT Segment；Segment EXPLAINS Concept。
- 管理知识点别名、先修关系来源及审核状态；自动抽取仅进入草稿。
- 先修关系发布前检查自环和循环；最大查询深度服务端限定为 2。
- 支持直接定位知识点回放，支持查询先修知识及对应本期片段。
- 无匹配知识点时回退普通 RAG；图谱没有关系时不生成虚构先修关系。
- 已知先修知识在本期无片段时明确说明无本期回放，不推荐无权限班期链接。
- 不把看过视频当作掌握知识，不做自动能力测评。

### F-009 Agent 编排与恢复
- 主线使用 Python LangGraph，工具为固定契约，业务写操作由服务端授权。
- 持久化 messages 摘要/窗口、当前任务、确认引用、申请引用、待人工原因等状态。
- 重启后恢复待确认任务，不重做已经成功的业务写入。
- 人工审批页面在业务 API 上完成事务；Agent 根据最新业务事实响应，checkpoint 不是事实源。
- 工具参数验证、超时、有限重试、总调用预算；失败不能编造成功。
- 单会话同一时刻最多一个生成任务；重复消息 ID 不重复执行；取消生成不会撤销已完成业务操作。

### F-010 评估、追踪与微调
- 固定版本评估集，含正常、多轮、历史版本、无答案、权限、重复操作、恢复和故障案例。
- 业务结果用确定性断言；语言质量评分需人工抽查。
- 记录 requestId/runId、模型/提示词/资料版本、工具状态、检索依据、延迟；日志脱敏。
- QLoRA 在业务契约稳定后做，训练客服行为、术语和工具使用，不记忆动态价格政策。
- 基座+基础提示词、基座+优化提示词、微调+相同优化提示词对照；训练验证测试按来源/模板族隔离。

## 6. 非功能需求

- 正确性：金额整数分，时间存 UTC；展示机构配置时区，不写死开发机时区。
- 安全：老师端授权、订单归属、受限检索和回放授权均有测试；知识内容视为不可信数据。
- 可恢复：业务事务+幂等+状态版本校验；持久化 checkpoint；索引任务可重试。
- 性能：采集首字、总时延 P50/P95、调用量与并发；第一轮记录硬件和基线后制定预算，不预造 SLA。
- 可运行：无需 GPU 的 mock 模型模式用于开发/CI；真实模型模式用于模型评估，结果明确区分。
- 可维护：锁依赖版本，说明环境变量，提供 setup/dev/seed/test/eval 命令；不提交密钥、真实学员资料或大模型权重。

## 7. 验收清单

| ID | Given / When / Then |
|---|---|
| AC-001 | 有两个班期不同权益；老学员问回放权益；引用本人版本而非最新宣传 |
| AC-002 | 访客询问我的订单；系统要求登录且不泄露个人数据 |
| AC-003 | 学员篡改他人报名、会话、申请、片段 ID；均无法访问 |
| AC-004 | 学员仅说想转班但未确认；数据库中没有已提交申请 |
| AC-005 | 草稿更新后点击旧确认卡；返回 409，要求查看最新摘要 |
| AC-006 | 同请求重试或重复调用；只有一张有效申请，返回同一 ID |
| AC-007 | 未知目标班期；可以申请，老师提出目标后须学员确认 |
| AC-008 | 两位老师并发批准；只执行一次，报名与审计保持一致 |
| AC-009 | 退费批准未登记执行；回复为批准待处理，不能说到账 |
| AC-010 | 工具超时但实际写入成功；恢复后查得原结果，不重复创建 |
| AC-011 | 待学员确认时服务重启；登录后可继续原任务，无重复写入 |
| AC-012 | 老师接管后学员发言；仅老师处理，机器人不抢答 |
| AC-013 | 学员问某知识点；返回本期有效片段、原文引用及真实时间位置 |
| AC-014 | 问某概念先修；只返回已审核关系，顺序先修在前且可追溯 |
| AC-015 | 图谱有外班期片段；本期学员看不到受限文本及可用播放地址 |
| AC-016 | 文档改版/删除；旧片段不可检索，失败重跑无重复数据 |
| AC-017 | 文档要求忽略权限/批准退费；系统不执行该指令 |
| AC-018 | 题目无知识覆盖；明确无依据，不编造片段/先修关系 |
| AC-019 | 图谱不可用；降级普通 RAG并说明无法核验先修，不伪造图谱结果 |
| AC-020 | 固定模型资料和测试集运行；生成带版本及分项结果的评估报告 |
| AC-021 | 重复消息/断线重连；无重复申请，最终状态可重新查询 |
| AC-022 | 学员撤回申请后老师处理；返回状态冲突，不再变更报名 |

## 8. 明确不做

- 多 Agent 团队、DSH 主线迁移、MCP 平台、Kubernetes、多租户 SaaS。
- 完整支付、优惠券、CRM、考试、自动批作业、就业推荐、视频转码/CDN。
- 自动退款决策、虚构规则、BERT 强制路由；BERT 可在主线完成后单独做对照实验。
- 让模型生成任意 SQL/Cypher、让学员 Agent 直接审批、把 Neo4j 当权限事实源。

## 9. 依赖与资料

运行依赖：PostgreSQL、Neo4j、Qdrant、Python Agent、TypeScript 业务 API、React；模型/Embedding 真实服务可替换为开发 mock。
待后续提供：授权课程字幕/讲义、真实班期信息、权益文字、脱敏业务样例。缺失时先用清楚标记的合成 seed，不能声称已验证真实课程质量。

## 10. 学习交付要求

AC 通过证明系统行为，不能证明学习者掌握。learning-plan.md 的 L-00～L-08 覆盖解释、独立修改、故障定位与实验分析。Claude 演示或代写练习不能计为学习者独立完成。
核心学习范围保留 LangGraph、受控工具、多轮状态、人机协作、RAG、知识图谱、评估、QLoRA、可观测性与稳定性。根据真实业务删除自动退费试算和复杂多课程推荐；BERT/DSH 仍为可选扩展，不为增加技术名词纳入主线。
